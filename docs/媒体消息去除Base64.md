# 图片、视频消息去除 Base64

日期：2026-11-02

## 范围和发送顺序

保留文本消息的 WS → MQ 异步入库链路，也保留文件消息先 HTTP 预存、获得远程地址，再 WS 投递的链路。本次没有改成上传中提前通知接收者，也没有调整消息 ID 或 ACK 协议。

图片、视频的新增流程：

1. 客户端生成小尺寸预览文件。Electron 通过本地文件 URL 显示选中的附件；Flutter 在本地生成图片缩略图或视频封面。
2. 请求现有 `/message/verifyUploadToken/{fileId}` 获取凭证和 `minioFilePath`。
3. 使用 HTTP multipart 调用 `/message/uploadPreview` 上传缩略图。
4. 原文件继续使用既有分片、断点续传、合并及 HTTP 消息预存流程。
5. 现有完成条件满足后再发送 WS 文件消息，图片内容不进入 JSON。接收者通过 HTTP 加载缩略图，点击后打开原图/原视频。

音频、普通文件不上传缩略图，沿用现有流程。

## 固定预览对象位置

原文件与预览使用同一个 MinIO 桶，预览对象名在原对象名后追加 `.preview`：

```text
原图/视频：bucket/yyyy/MM/dd/fileId
缩略图：  bucket/yyyy/MM/dd/fileId.preview
```

消息不新增数据库字段。原来的 `remote_path`、`remote_url` 足以定位两个对象，预览访问地址为 `remoteUrl + '.preview'`。HTTP/WS 响应中的 `previewUrl` 为计算属性，不落库；客户端 WS 编码时只发送原文件元数据，本地预览路径不发送。

## HTTP 预览上传协议

`POST /message/uploadPreview` 的 multipart 字段：

| 字段 | 内容 |
| --- | --- |
| `preview` | JPEG/PNG 二进制文件 |
| `fileId` | 原文件 ID |
| `verify` | 现有文件上传凭证 |
| `fileType` | 2 图片、3 视频 |

返回 `Result<String>`，data 为远程预览 URL。接口与分块上传一样在业务层验证上传凭证。服务端将凭证对应的原对象路径存入带 TTL 的 Redis 辅助键，客户端无法指定任意预览写入路径。

预览限制为 1 MiB，长宽不超过 1024 像素；服务端检查真实图像格式和尺寸，拒绝无效文件。正常客户端预览长边最多 320 像素。MinIO 写入失败返回失败，不伪装成上传成功。桶沿用原图片/视频桶，不新增桶，预览对象的 HTTP GET 必须与原文件一样可访问。

## 三端修改

### Java

- 移除私聊、群聊请求/响应、HTTP DTO、数据库实体和历史响应中的 `previewBase64` 字段。
- `MessageMapper.xml` 不再写 `preview_base64`；现有实体不再映射该字段。历史查询也不把它返回给客户端。
- 预览图只走 HTTP → MinIO；WS 转发、MQ 入库/离线消息的当前消息模型不包含图片内容。
- HTTP 上传预览复用现有文件凭证，原文件分片与合并不重写。
- WS 单帧载荷上限与自定义协议完整消息上限从 128 KiB 统一降为 64 KiB，共用 `ProtocolFrameDecoder.MAX_FRAME_LENGTH`，避免两处设置不一致。完整应用消息包含 16 字节协议头，因此 JSON 正文最多为 65,520 字节，不是字符数。即使拆成多个 WS 帧，应用消息仍受自定义解码器的总长度限制。HTTP 握手聚合上限保持原值。
- 64 KiB 是本次选择的保守限制，尚未经实际最大群成员列表、长文本和引用内容验证。主要收益来自实际消息体变小，不声称仅调低上限就已提高吞吐量。超限消息会被协议层拒绝，需人工检查业务边界。

### Electron

- FFmpeg 生成 JPEG 预览文件，不再转换为 Base64；本地预览目录为用户数据目录下的 `media-previews`。
- 视频封面取首个可解码画面，避免固定取第 2 秒导致短视频失败。截图同样将预览单独保存为文件。
- 上传时先上传预览文件，再沿用原文件上传与消息预存；预览失败会终止本次发送并标记上传失败。
- 图片/视频卡片通过远程预览加载；发送者当前界面可继续使用本地预览文件。
- 新 SQLite 建表移除 `preview_base64`。已有 SQLite 中的旧列不再映射写入，也不带回渲染缓存，没有自动删列或清空已有数据。
- WS 编码处过滤旧缓存中的 Base64 字段、本地预览地址和路径，避免历史失败消息重发时重新携带图片内容。

### Flutter

- 图片通过 Flutter 图像 API 生成最长边 320px 的 PNG，不新增依赖。
- Android 使用 `MediaMetadataRetriever`，iOS 使用 `AVAssetImageGenerator`，在后台线程生成视频首帧 JPEG，通过 MethodChannel 返回字节，再走 HTTP 上传。
- Flutter Windows 通过本机 FFmpeg 生成真实视频画面封面，优先使用应用程序目录中的 `ffmpeg.exe`，否则从 PATH 查找。本机开发环境已存在 FFmpeg，本轮未安装或下载。使用参数数组启动进程，封面以 JPEG 字节从 stdout 返回，不生成 Base64；读取 stderr 并设置 20 秒生成上限，超时关闭子进程。提取失败会明确报错，不再用通用图标冒充真实封面。
- Flutter Web/其他桌面平台保持视频发送，使用小型通用视频图标封面；Android/iOS 和 Electron 沿用各自真实视频封面提取。
- 聊天气泡只加载缩略图；打开预览页时再获取原图/原视频。
- 旧消息缓存载入时丢弃内嵌预览，后续本地保存不再写回；WS 编码层也过滤旧字段。

## 历史消息与数据库操作

数据库删除由用户自行执行，本次没有连接或修改实际数据库。

- 服务端旧列是 `message.preview_base64`，新版本代码已不依赖它，可由用户删除。没有需要新增的预览地址列。
- Electron 已有本地 SQLite 旧列可以保留，新版本不会继续写；若用户自行删除也不影响新版本消息读取。新安装不会创建该列。
- 仓库初始建表脚本只同步删除列定义；它不是迁移脚本，不需要重新导入整份脚本。
- 旧消息没有 `.preview` 对象时：图片卡片回退原图，视频显示可点击播放的占位。删除旧 Base64 不会自动生成历史视频封面。
- 未对历史 MinIO 对象、旧数据库内容或服务器队列执行批量迁移/清理。

## 启用与验证边界

### 视频上传与消息确认状态修复

Electron 的文件上传与 WS ACK 是两个阶段：现有 ACK 计时本来就在上传完成、准备 WS 投递时才开始，不能用延长消息超时掩盖上传挂起。

- 视频、图片上传期间显示上传百分比、暂停或正在合并；完成后才显示等待服务器确认的图标。ACK 超时仍按既有 5 秒计算，不包含文件上传耗时。
- 文件完成事件不再提前将 SQLite 消息标记为发送成功；上传可用状态仍按现有 HTTP 接口同步，消息成功由 ACK 更新。
- WS 发送时复用当前界面记录并更新状态；待确认记录保留原消息引用，切换会话清理缓存后仍能处理 ACK。超时、发送失败写回本地状态；迟到 ACK 即使对应界面记录已经回收，也会更新本地数据库。
- 文件读取、线程池分块处理、分片接口业务失败会回报上传失败、停止后续任务，不再只输出日志并永久等待合并。分块只传实际有效字节，避免末块包含缓冲区多余数据。
- Flutter 的文件发送已在上传、合并与 HTTP 保存之后才调用 WS 发送，20 秒 ACK 计时不包含上传阶段，本次未修改其计时。

此修复同样未运行测试或构建。人工检查应包含大于 5 秒的视频上传、上传过程中切换会话后返回、读取失败/分片失败、超时后迟到 ACK、完成后重新打开会话，确认不再一直显示发送中。修改主进程后需完整重启 Electron。

先部署并重启包含 common-storage 更新的 `im-chat`、新模型的 `im-server` 以及放行新上传路径的 `im-gateway`，再完整重启更新后的 Electron、重新打包安装 Flutter。Flutter 有 Android/iOS 原生变更，热重载不够。没有新增包，无需额外安装依赖。

按用户要求，本轮未运行测试、编译、构建、依赖安装或真实接口联调。仅做源码核对和差异空白检查；截图测试的隔离文件边界已按新的预览文件流程调整，未执行。

人工检查建议：

1. Electron → Flutter、Flutter → Electron，分别发送图片、短视频和群聊媒体，确认收到预览、打开原文件正常。
2. 检查 WS 请求、响应和 MQ 消息：不存在 `previewBase64`、`preview_base64` 或 `data:image/...;base64,...`；只有元数据/地址。
3. MinIO 中每条新图片/视频有原文件与 `.preview` 对象；在另一设备上直接访问预览 URL，确认类型为 image/jpeg 或 image/png。
4. 重新打开会话、重启客户端、拉取历史，确认预览无需数据库 Base64；旧图片回退原图、旧视频仍可播放。
5. 预览上传失败时不投递 WS；检查正常完成、原文件上传失败、暂停恢复、小文件先完成时序和失败重发。
6. 检查截图、相机图片、GIF、长图、HEIC 和横竖屏视频；格式支持取决于客户端 FFmpeg、Flutter 图像解码器或系统媒体能力。
